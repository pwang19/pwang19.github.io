Runtime analyzer

At a former employer I built a tool that tracked how long thousands of test plans took to run each day, so teams could see when their suites got slower. This is a pared-down version you can play with.

All data here is synthetic: made-up suites, made-up numbers.

One of these test suites got slower and stayed slower. Pick a suite, then click the day you think the regression landed.

Suite

What changed on day 18

Five payments tests account for the whole slowdown. The other 14 didn't change.

TestBeforeAfterChange
refund flow1.9 min3.4 min+1.5
saved-card checkout2.1 min3.3 min+1.2
split payment1.6 min2.5 min+0.9
currency conversion1.2 min1.7 min+0.5
receipt email0.9 min1.0 min+0.1

The culprit was commit 3f9c2ab, "fixture: create users per test instead of sharing seeded ones". Every test now paid for its own setup.

What the real tool did

  • Collected runtimes for every test plan in every pipeline run, every day
  • Flagged suites whose runtime stepped up and stayed up, not one-off spikes
  • Answered "what got slower, and when?" through an MCP server, so Claude and Cursor could ask it directly
